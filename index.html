企业用不上，是因为数据没有整理，指标没有定义，没有人能判断结果对不对，出了错没有人负责。三顾做的就是这四件事。

您可能遇到过这四种情况

  1. 不知道先做哪一件事

    都说要用 AI，但不知道在自己的企业里先做哪一件事，做成什么样才算有用。

  2. 招不到人，也判断不了人

    想招一个懂 AI 的人。本地招不到，外地来的人，也判断不了他是不是真的会做。

  3. 做了，没有看到结果

    人招来了，或者软件买来了，几个月过去没有看到结果。数据分散在进销存、财务系统和各种表格里，同一个数字几个部门算出来不一样。

  4. 做完了，说不清对不对

    找过外包。报价从几千元到几百万元都有，做完之后说不清它答得对不对。

这四件事是连在一起的。任务没有说清楚，招人就没有标准，验收也没有依据。只解决其中一件，结果还是出不来。

我们能做的事

四个方面，十八类工作。第一个项目从其中一类开始，具体做哪一类由诊断决定。

把数据看清楚

先有一份全公司都认的数字。

销售额386.2万元
毛利率30.4%

  • 数据整理和指标定义

    把进销存、财务系统和各种表格里的数据接到一起，清洗干净。每个指标只留一种算法，由您的负责人确认。

  • 经营看板和报表

    每周自动生成的经营报表，和可以点击查看的看板：趋势、排名、对比、地图和明细。

  • 数据问答

    用平时说话的方式提问，系统从您的数据里查出数字，并写明用的指标定义和时间范围。

  • 专题分析报告

    针对一个具体问题写给管理层的报告，例如线上线下比价、门店评估。有结论，有依据，有建议。

把决策算清楚

把经验里的判断写成可以计算、可以检验的规则。

  • 定价和促销

    线上线下比价，调价规则，不同商圈的差别定价。先在少数门店试，再推广。

  • 需求预测

    按门店、按品种预测销量，用于订货、排班和促销备货。

  • 库存和补货

    安全库存和补货建议，缺货和滞销的预警，多个供应商之间的订货分配。

  • 品类和选品

    给商品分类分组，提出淘汰和引进的建议，必须保留的品种设保护规则。

  • 门店网络和选址

    把每家店的经营数据和位置放在一起，评估现有门店，分析在哪里开店。

  • 排班、排产和配送

    把人员排班、生产排程和配送路线写成优化问题来求解，约束条件由您确认。

把重复的工作交出去

模型做重复的部分，人做确认。

  • 业务智能体

    把一项重复的判断工作交给智能体，例如品类淘汰、补货建议、比价和对账。每条建议都由您的员工确认。

  • 文档识别和录入

    把纸质文件和照片识别成文字，再按栏目整理成表格，例如单据、合同和产品说明书。认不清的地方标出来，由人核对后入库。

  • Skill

    把一项工作的步骤、规则和例子写成模型可以照着执行的说明。换人、换模型，这项工作的做法都留在企业里。

  • Harness

    搭建模型运行的环境：能调用哪些工具、读哪些数据，每一步留下记录，出错时停下并通知人。

做过的项目

下面的项目由创始人在一家连锁零售企业主持。这家企业是连锁药店，有约 160 家直营门店，项目涉及定价、品类和门店网络。

品类淘汰智能体

背景
这家企业每个季度要决定哪些商品淘汰。这项工作原来每季度要花 100 多小时。
做法
创始人搭建了一个品类淘汰智能体，也就是一个能按规则连续完成多步任务的 AI 程序。它把每个商品归入可以互相替代的竞争组，按销量、毛利、价格和趋势给淘汰候选打分，并对慢病用药、品类覆盖和线上主力品设置保护规则。员工对每条建议选择采纳或否决并写明理由，这些理由会转成修正后的规则，用于下一轮建议。
结果
智能体已运行六个月以上，建议采纳率超过 95%，每季度的品类淘汰工作从 100 多小时减少到 1 小时以内。

这是一个项目在一家企业的结果。您的项目要达到什么结果，由诊断确定并写进验收测试集。

药品说明书录入

背景
药品说明书要录进系统。纸质说明书字迹模糊，版式复杂，手工打字耗时。
做法
员工拍下说明书的照片。系统先识别文字，再按通用名称、成份、功能主治、用法用量、批准文号等栏目整理成表格。认不清的地方标出来，由员工核对后入库。

线上线下比价

背景
同一个商品，门店和线上平台的价格不一样。价格表每周更新，靠人工逐行对比看不过来。管理层要判断现在的价格安排哪些合理，哪些不合理。
做法
每周把门店和两个线上平台的价格放进同一张表，保留最近四周，计算每个商品的差价，找出差价大的商品和品类。写成给员工和管理层看的分析报告，说明现有安排合理和不合理的地方，并给出调整建议。
交付
一份分析报告，和一个可以按品类、平台、周次点击查看的看板。

门店网络评估

背景
管理层要判断哪些门店需要调整，新店开在哪里。门店的经营数据在月度报表里，位置在地图上，原来是分开看的。
做法
把每家门店十二个月的经营数据和它的坐标放在一起。在地图上按经营情况给门店着色，标出彼此距离近的门店和没有门店的区域。写成给管理层看的评估报告，附一张可以筛选和导出的门店表。
说明
评估用的是经营数据和位置。门店经营不好，也可能是人员安排或周边竞争变化造成的，这部分由管理层结合实际情况判断。

我们做事的六条原则

  • 一次只做成一件事

    做什么、不做什么、怎样算做成，开工前写清楚。项目是固定总价，不按人头和天数收费。

  • 结果由您检验

    验收看测试题的通过比例，不看演示，也不看我们的说法。

  • 把人留下

    项目做完，您的企业里要有人会用、会改。接手的人由我们的工程师指导和培训。选人只看实作结果：在限定时间内用真实类型的数据完成任务。

  • 数据怎么用，由您定

    模型可以调用 API，也可以部署在您自己的服务器上。用 API 时，哪些数据可以发给模型，事先写进协议。我们对您的业务系统只申请只读权限，不保留副本。进场前签保密与数据处理协议。

  • 不承诺做不到的事

    我们不承诺用了 AI 销售额会增长多少。我们承诺的是合同里写明的结果通过验收。

  • 不卖您不需要的软件

    我们不卖通用软件。市场上已有的软件够用时，我们帮您把它用起来。

关于三顾

“三顾”取自三顾茅庐：刘备三次上门，请诸葛亮出山。这个名字说的是我们做的两件事。第一，帮企业找到并留下会做事的人。第二，我们的服务本身是上门三次：诊断、项目、配人。英文名 Thrice，意思是“三次”。

第一次上门写出的诊断报告叫“隆中对”。它写清楚先做什么、不做什么，怎样算做成。

常见的问题

为什么不自己招一个人，或者直接买一套软件？

自己招人有两个难处。有经验的人不在本地，招来之后也很难判断他是不是真的会做。他还要独自面对没有整理的数据和没有说清楚的任务。买软件的难处在数据：数据问答这类功能准不准，取决于企业有没有统一的指标算法，数据没有整理时软件用不起来。三顾先把数据和指标整理好，把第一件事做成，再帮您配人，或者把买来的软件用起来。

工程师现在都用 AI 写代码，你们和别的服务商有什么不同？

写代码的速度没有不同，我们用的是同样的工具。不同在工具之外的三件事：把您的话变成可以计算的指标定义，了解您企业的数据，核对 AI 写出的查询。每个项目都用您确认过答案的测试题验收，这一条写进合同。

AI 更新很快，现在做的系统会不会过时？

模型会换。您的数据、指标的算法和验收测试题不会因为模型更换而作废。更换模型或系统之后，用同一套测试题重新检验，通过了再继续用。

一定要把模型部署在我们自己的服务器上吗？

不一定。可以直接调用模型服务的 API，上线快，成本低。数据不能离开内网时，再做私有化部署。用 API 时，哪些数据可以发给模型，事先写进协议。两种方式都用同一套测试题验收。

项目需要我们配合什么？

三件事。第一，指定一位负责人，指标怎么算、哪个数字为准，由他决定并签字。第二，安排两到三次访谈，每次约一小时，对象是您本人、相关的部门负责人和管系统的人。第三，提供只读的数据访问，以及几张现在正在用的报表。

我们不在温州，可以做吗？

可以。温州以外的项目用三次出差完成，差旅费用另计。
